# 6. IDとバージョン

## 6.1 StableId

確定形式：

```text
^[a-z][a-z0-9_]{2,79}$
```

制約：

- 3文字以上
- 80文字以下
- 小文字英字で開始
- 小文字英字、数字、アンダースコアのみ
- 前後空白禁止
- 自動trim禁止
- 自動小文字変換禁止
- 改行禁止
- 表示名をIDにしない
- enum indexをIDにしない

現行実装は長さ制限がなく、`a`を許可しているため修正が必要。

## 6.2 CatalogVersion

確定形式：

```text
YYYY.MM.DD.REVISION
```

例：

```text
2026.09.17.1
2026.09.17.2
```

制約：

- 年は4桁
- 月は01～12
- 日は実在日
- REVISIONは1以上の整数
- 前後空白禁止
- 改行禁止
- 大文字・英字・ハイフン・アンダースコア禁止
- 完全一致で比較
- SemVerとして比較しない

現行実装は`v2`、`catalog-v2_1`、`V2-beta.1`等を許可するため修正が必要。

# 7. 数値計算

金額、ポイント、率の確定計算に`double`を使用しない。

使用する型：

```text
MoneyYen
PointAmount
Rational
Rate
MicrosYen
```

## 7.1 MoneyYen

共通値オブジェクトでは負数を許可する。

用途：

- 返金
- 取消
- 調整
- 差分

通常購入額等の非負制約はDomain型で実施する。

## 7.2 PointAmount

共通値オブジェクトでは負数を許可する。

通常付与ポイントはDomain型で0以上に制約する。

## 7.3 Rate

率はRationalで保持する。

例：

```text
0.5%  = 1 / 200
1.0%  = 1 / 100
1.25% = 1 / 80
1.5%  = 3 / 200
```

## 7.4 丸め

対応する丸め：

```text
towardZero
floor
ceiling
halfAwayFromZero
exact
```

`exact`は割り切れない場合にエラーとする。

enum indexを保存しない。安定した文字列名を保存する。

# 8. 条件評価

条件評価値：

```text
satisfied
notSatisfied
unknown
notApplicable
```

型名は既存コードへの影響を抑えるため、当面`TriState`を維持する。ただし実態は4状態である。

## 8.1 NOT

```text
satisfied     → notSatisfied
notSatisfied  → satisfied
unknown       → unknown
notApplicable → notApplicable
```

## 8.2 AND

`notApplicable`は評価対象外として扱う。

優先順位：

1. notSatisfied
2. unknown
3. satisfied
4. 全要素notApplicableならnotApplicable

二項表：

| A | B | A AND B |
|---|---|---|
| satisfied | satisfied | satisfied |
| satisfied | notSatisfied | notSatisfied |
| satisfied | unknown | unknown |
| satisfied | notApplicable | satisfied |
| notSatisfied | satisfied | notSatisfied |
| notSatisfied | notSatisfied | notSatisfied |
| notSatisfied | unknown | notSatisfied |
| notSatisfied | notApplicable | notSatisfied |
| unknown | satisfied | unknown |
| unknown | notSatisfied | notSatisfied |
| unknown | unknown | unknown |
| unknown | notApplicable | unknown |
| notApplicable | satisfied | satisfied |
| notApplicable | notSatisfied | notSatisfied |
| notApplicable | unknown | unknown |
| notApplicable | notApplicable | notApplicable |

## 8.3 OR

優先順位：

1. satisfied
2. unknown
3. notSatisfied
4. 全要素notApplicableならnotApplicable

二項表：

| A | B | A OR B |
|---|---|---|
| satisfied | satisfied | satisfied |
| satisfied | notSatisfied | satisfied |
| satisfied | unknown | satisfied |
| satisfied | notApplicable | satisfied |
| notSatisfied | satisfied | satisfied |
| notSatisfied | notSatisfied | notSatisfied |
| notSatisfied | unknown | unknown |
| notSatisfied | notApplicable | notSatisfied |
| unknown | satisfied | satisfied |
| unknown | notSatisfied | unknown |
| unknown | unknown | unknown |
| unknown | notApplicable | unknown |
| notApplicable | satisfied | satisfied |
| notApplicable | notSatisfied | notSatisfied |
| notApplicable | unknown | unknown |
| notApplicable | notApplicable | notApplicable |

## 8.4 nullable bool変換

既存の`toNullableBool()`は後方互換のため残す。

```text
satisfied     → true
notSatisfied  → false
unknown       → null
notApplicable → null
```

ただし、この変換は`unknown`と`notApplicable`の区別を失うため、永続化、条件判定、監査ログには使用しない。

`fromNullableBool(null)`は`unknown`を返す。`notApplicable`は明示的に生成する。

# 9. confidence

計算結果のconfidence：

```text
confirmed
estimated
conditional
unknown
ineligible
```

条件の`unknown`を暗黙にtrueまたはfalseへ変換しない。

カテゴリ名だけで加盟店を推測した場合は原則`estimated`とする。

一次情報と対象加盟店が明示的に一致する場合に`confirmed`へ昇格できる。

# 10. 日付と有効期間

有効期間：

```text
[validFrom, validUntilExclusive)
```

判定：

```text
validFrom <= date
date < validUntilExclusive
```

`validUntilExclusive`がnullなら終了なし。

汎用`ValidityPeriod`は空期間を表現できる。

```text
start == end
```

ただしactiveカタログ項目は空期間を禁止する。

active項目：

```text
validFrom < validUntilExclusive
```

内部処理はUTCを基準とする。日本の制度日付へ変換するときはAsia/Tokyoを明示する。端末の暗黙タイムゾーンへ依存しない。

同一処理中にClockを複数回呼ばず、開始時に基準時刻を1回取得する。

# 19. 商品ルール

## 19.1 みずほ楽天カード

通常楽天ポイント：

```text
100円につき1楽天ポイント
```

Wポイント：

- 2025-06-30以降の新規申込・契約完了
- 申込日の翌々月末までに口座振替設定完了
- 両条件を満たした月の月初から開始
- 最長1年間
- 楽天通常ポイントと同数のみずほポイント
- みずほポイント上限10,000
- 通常ポイント対象外ならmirrorも対象外
- SPU、キャンペーン、期間限定上乗せをmirrorしない

旧4条件をWポイントの必須条件にしない。

通常ポイント：


```text
追加されたカード側の制度を適用
Olive本体の通常還元や年間特典を適用しない
```

- credit対象
- debit対象
- pointPayment対象外
- addedCard対象外
- 10,000 Vポイント
- 最大1回
- 通常ポイントと別ルール
- 今回獲得ポイントへ無条件加算しない
- 年会費無料判定とポイント付与を別ルールにする

secondaryArticleまたはuserReportだけの制度は、draftまたはunverifiedとする。

公式本文が変更された場合：

- 既存Sourceを削除しない
- accessStatusをchangedにする
- 新contentHashまたは新Sourceを登録する
- 変更前の根拠を履歴として保持する

# 23. JSON Schema契約

JSON Schemaは次を使用する。

```text
JSON Schema Draft 2020-12
```

各Schemaの`$schema`：

```json
"$schema": "https://json-schema.org/draft/2020-12/schema"
```

`$id`は所有未確認のWebドメインを使わず、URNを使用する。

例：

```json
"$id": "urn:bestpay:schema:catalog-root:1.0.0"
```

共通方針：

```text
additionalProperties = false
requiredを明示
StableIdはpatternとminLength/maxLengthを併用
CatalogVersionはpatternに加えてアプリ側で実在日を検証
金額はinteger
ポイントはinteger
率はnumerator/denominator
日時はdate-time
制度日付はdate
null許可は型配列で明示
enum index禁止
```
