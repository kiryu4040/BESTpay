# スコープと期（何をいつ作るか）

決定台帳 `decision_ledger.json` の `phase` をまとめたものです。
**機能を思いつきで足すのではなく、この期を移動させて表現します。**

- **第1期 = 実用開始ライン**（これが終わると店舗で実際に使えます）
- **第2期 = 完成**（あなたの言う「全体を完成させる」の中身）
- **第3期 = やらない**（作らないと決めたもの。記録として残す）
- **運用 = 開発の進め方**

---

## 第1期：実用開始ライン

### 土台
- `docs/decisions/` の決定記録を正本として運用（D-01〜D-06, D-36）
- ビルドは GitHub Actions（PC不要）（D-03, D-04）
- Flutter 3.24.5 / JDK 17 / API 34 で固定（D-06）

### データ（カタログ）
- 優先度A 6枚のカード：みずほ楽天カード / Oliveフレキシブルペイ ゴールド /
  三井住友カード ゴールド（NL）/ 三菱UFJカード / JCBカードW / V NEOBANKデビット（D-34）
- カタログ13ファイルの枠を用意し、うち8ファイルに実データ（D-35）
- 主要チェーンの店舗データを登録。**カードの公式特典が言及するチェーンから逆算して決める**（D-72）
- 店舗個別の上乗せ特典（決済経路で区別）（D-73）
- 主要QR（楽天ペイ / PayPay / d払い / FamiPay / VポイントPay）へのチャージ関係（D-74）
- 提示ポイント（Ponta / dポイント / 楽天ポイント / Vポイント）（D-75）
- 情報源の登録（activeルールには公式一次情報源が必須）（D-38）

### 計算
- 確定円換算価値の降順でランキング（D-41）
- 同順位の決定的タイブレーク（D-42）
- 初期10件 → 20件ずつ追加（D-43）
- 条件付きは別枠（D-44）／未保有カードは参考扱い（D-45）
- 金額未入力時は名目率比較（D-46）／金額の入力制約（D-47）
- 日付の必須・任意と境界警告（D-48）
- 月間・年間の集計額は手動入力（D-49）
- 未入力条件は unknown（D-50）／ポイントは種類ごとに表示（D-51）
- 「最大」表記の徹底（D-52）／年会費はランキング外（D-54）
- 四値と confidence の区別（D-56）
- 整数・分数・MicrosYen・BigInt（doubleを使わない）（D-63）

### 画面
- 5タブ：ホーム / 店舗 / 電卓 / 年間 / 設定（D-07）
- ホーム＝履歴系を除いた実用ダッシュボード（D-08, D-78）
- 初回起動フロー（強制入力を求めない）（D-11）
- 戻る操作・入力保持（D-12）／route ID で実装（D-13）
- 店舗×カードランキング＋還元詳細（D-16, D-17）
- カード管理・条件設定・ポイント価値設定（D-18）

### 保存
- SharedPreferences に集約（D-57）／provider 継続（D-58）
- カタログはアセット同梱＋起動時検証（D-61）
- ID形式の固定（D-64）／表示名とapplicationId（D-65）
- 依存方向の規約（D-60）／v1コードと番犬テストの維持（D-59）

## 第2期：完成

- 電卓タブ（D-22）
- 年間タブ：達成状況・残額・比較対象カード設定・カード詳細（D-23）
- **年間の手動配分**（D-76）— 複数カードへ利用予定額を割り当てて配分全体の価値を試算。自動最適配分はしない
- **段階特典・回数型特典**（D-77）— 累積型と到達型を区別、回数型は1回あたり価値×想定回数
- 年間ボーナスの分離表示（D-53）
- バックアップ／復元（**他の機能より先に実装**）（D-25）
- データ情報画面（D-26）／アプリ情報・免責（D-27）／データ削除・初期化（D-30）
- 空状態・エラー・オフラインの共通部品（D-14）／テーマ（D-15）
- 情報の鮮度基準と警告（D-39）／20%超の警告（D-55）
- アクセシビリティ（D-69）／免責表示（D-70）
- アイコン作成（D-66）／重複ファイル整理（D-68）
- ヘルプは作らず、エラー時の技術情報表示のみ（D-29）

---

## 第3期：やらない（記録として保持）

| 項目 | 理由 |
|---|---|
| お気に入り機能（D-09, D-10, D-71） | 個人利用で不要と判断。ホームの履歴表示も廃止（CR-049〜051） |
| 通知機能（D-28） | 個人利用では使われない |
| CSV利用明細の取込（D-31） | 将来機能 |
| iOS対応（D-32） | Androidのみ |
| オンラインでのカタログ更新・署名検証（D-33） | 手元でJSONを更新して再pushで足りる |
| ヘルプ記事・診断共有（D-29の一部） | 納品物と資料で代替 |
| 自動最適配分（D-76） | 資料でも非実装と明記 |
| カード会社との口座連携・明細自動取得 | 資料の対象外 |

---

## 運用

| 項目 | 内容 |
|---|---|
| コードの反映 | 変更ファイルを納品 → Windowsで配置してcommit/push（D-01, D-02） |
| APKの入手 | GitHub Actionsのartifactをスマホで取得（D-03） |
| ブランチ | `feature/pr-XX-...` とPRの流れを踏襲（D-05） |
| カード追加 | `card_addition_runbook.md` の6段のみ（D-36） |
| テスト | 既存57本＋カードごとの境界・端数・上限・対象外テスト（D-67） |
| 変更管理 | 決定台帳へ追記 → 矛盾確認 → 期の移動で表現 |
