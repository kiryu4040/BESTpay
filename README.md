# BESTpay v2

店舗と金額を入力すると、保有カードの還元額ランキングを表示する個人利用の Android アプリです。
このリポジトリを GitHub にアップロードすれば、**GitHub Actions が自動で APK（スマホに入れるアプリ本体）をビルド**します。パソコンでのコマンド操作は一切不要です。

---

## このリポジトリの読み方（はじめての方向け）

| `lib/` | アプリの本体（画面と計算ロジック） | 基本は触らない |
| `lib/ui/` | 画面（ホーム/店舗/電卓/年間/設定の5タブ） | 基本は触らない |
| `lib/domain/` | 還元額の計算エンジン | 基本は触らない |
| `lib/core/` | 金額・ポイントなどの基本部品 | 基本は触らない |
| `test/` | 計算ロジックの自動テスト | 触らない |
| `android/` | Android アプリ化のための土台 | 触らない |
| `.github/workflows/build-apk.yml` | APK を自動ビルドする仕組み | 触らない |
| `docs/decisions/` | 設計の決定記録とカード追加手順 | **カードを増やすときに読む** |
| `00_START_HERE.txt` | このフォルダの説明書 | 最初に読む |

## APK をスマホに入れるまでの流れ

### 1. このリポジトリを GitHub にアップロードする

1. GitHub にログインし、右上の「+」→「New repository」で新しいリポジトリを作る（名前は自由。例: `bestpay-v2`）
2. できたリポジトリのページで「uploading an existing file」のリンクを開く
3. このフォルダの**中身すべて**（`.github` フォルダごと）をドラッグ＆ドロップしてアップロードし、「Commit changes」で確定する
   - ※ `.github` のようにドットで始まるフォルダも必ず含めてください。これが無いと自動ビルドが動きません

### 2. APK が自動でビルドされるのを待つ

1. アップロード（＝push）すると自動でビルドが始まります
2. リポジトリのページ上部の「**Actions**」タブを開く
3. 一覧の一番上にある「Build Android APK」をクリックし、「Build APK」というジョブを開く
4. 緑色のチェックマークが付けばビルド成功です（5〜10分かかります）
5. 失敗（赤い×）の場合はジョブを開いてエラー文を確認してください

### 3. APK をダウンロードする

1. ビルド成功した「Build Android APK」のページを**下にスクロール**する
2. 「**Artifacts**」という欄にある「**BestPay-APK**」をクリックすると ZIP がダウンロードされます
3. ZIP を解凍すると中に `BestPay.apk` があります

### 4. スマホにインストールする

1. `BestPay.apk` をスマホに送る（スマホのブラウザで GitHub にログインしてダウンロードするのが簡単です）
2. APK をタップして開く
3. 「提供元不明のアプリのインストール」を許可するか聞かれたら許可する
4. インストール完了。動作要件は **Android 8.0（API 26）以降** です

> ヒント: 「Actions」タブの「Build Android APK」→ 右上の「**Run workflow**」ボタンを押すと、変更がなくてもいつでも手動でビルドできます。

## いま出来ること / これから出来ること

- いま: 5タブの画面骨格が動きます。カードの実データはまだ入っていないため「カタログはまだ空です」と表示されます（異常ではありません）
- これから: カードを増やすときは **`docs/decisions/card_addition_runbook.md`** を読んでください。計算エンジンはすでに正しい構造で入っているため、カードが増えても作り直しは不要です

## 技術メモ（開発者向け）

- Flutter 3.24.5 / JDK 17 / compileSdk 34 / minSdk 26 / targetSdk 34
- applicationId: `com.bestpay.app`
- 依存パッケージは `provider` のみ（意図的に最小化）
- アーキテクチャの依存ルールは `tool/check_architecture.dart` と `test/architecture/dependency_rule_test.dart` で機械的に検査される
- `pubspec.yaml` には意図的に assets 宣言を入れていない（`assets/data/` は次フェーズで追加。先に宣言するとビルドが失敗するため）
